# Техническое задание: AST-TOC Daemon (Python)

## 1. Назначение и цели
Создать инструмент **AST-TOC** для языка **Python**, который:
- добавляет и обновляет структурный хедер (TOC) в каждом `.py` файле каталога `./src` на основе разбора AST;
- работает в виде демона (фонового процесса), отслеживающего изменения файлов;
- предоставляет CLI с командами: `ast_toc start | stop | status`.

Цели:
- обеспечить единый, машинно-генерируемый «оглавительный» блок в каждом файле;
- поддерживать хедер в актуальном состоянии при изменении кода;
- снизить трудозатраты на документацию и повысить прозрачность архитектуры.

## 2. Термины и определения
- **AST-TOC** — авто-сгенерированный хедер с описанием содержимого файла (классы, методы, функции и т. п.).
- **Демон** — фоновый процесс, отслеживающий файловые события и обновляющий хедеры.
- **Маркерная область** — участок файла между маркерами, куда пишется/обновляется AST-TOC.

## 3. Область применения (Scope)
Входит:
- Python-файлы (`*.py`) в `./src` (рекурсивно).
- Вставка/обновление AST-TOC при создании, изменении, переименовании файлов.
- Парсинг Python-AST: обнаружение классов, методов, функций, импортов.
- CLI с `start/stop/status`, PID-файл, логи, конфиг.

Не входит (MVP):
- Автоматическое извлечение «назначения файла» из естественного языка.
- Поддержка языков, кроме Python.
- Интеграция с VCS/PR (можно запланировать).

## 4. Функциональные требования
### 4.1. Хедер (AST-TOC)
Хедер должен размещаться в начале файла и содержать:
- `FILE_TOC` (идентификатор).
- `Module`: относительный путь от корня репозитория.
- `Purpose`: назначение файла (или `TODO: fill purpose`).
- `Classes`: список классов и методов.
- `Functions`: список модульных функций.
- `Imports`: список импортов верхнего уровня.
- `Updated`: дата/время последней генерации (UTC).
- `Generated-By`: `ast_toc vX.Y.Z`.

**Пример:**

```text
# === FILE_TOC BEGIN ===
# Module: services/identity/auth_service.py
# Purpose: TODO: fill purpose
# Classes:
#   - AuthService:
#       - issue_token(credentials)
#       - refresh(token)
# Functions:
#   - helper(x, y=0)
# Imports:
#   - from typing import Optional
#   - import json
# Updated: 2025-09-26T12:34:56Z
# Generated-By: ast_toc v1.0.0
# === FILE_TOC END ===
```

### 4.2. Позиция хедера
- По умолчанию — в начале файла.
- Если есть модульный docstring, хедер вставляется **над** ним.

### 4.3. Извлечение структуры (AST)
- Извлечение классов, методов, функций, импортов через модуль `ast`.
- Сигнатуры без аннотаций типов и значений по умолчанию.
- Вложенные функции игнорируются (MVP).

### 4.4. Демон
- `ast_toc start` — запускает мониторинг каталога, обновляет TOC.
- `ast_toc stop` — завершает демон по PID.
- `ast_toc status` — выводит `running` + PID или `stopped`.

### 4.5. Исключения
- Игнорируются `.git`, `.venv`, `__pycache__`.
- Поддержка include/exclude паттернов.
- Игнорирование файлов > N МБ (по умолчанию 1 МБ).

### 4.6. Безопасная запись
- Атомарная запись (tmp-файл + rename).
- Сохранение кодировки и перевода строк.

### 4.7. Логирование
- Уровни: INFO/ERROR/DEBUG.
- Лог-файл: `.ast_toc.log` (ротация).

### 4.8. Конфигурация
Файл `.ast_toc.yaml` в корне проекта:

```yaml
watch_path: "./src"
pid_file: ".ast_toc.pid"
log_file: ".ast_toc.log"
log_level: "INFO"
insert_above_docstring: true
include:
  - "**/*.py"
exclude:
  - "**/__pycache__/**"
max_file_mb: 1
header:
  begin_marker: "# === FILE_TOC BEGIN ==="
  end_marker: "# === FILE_TOC END ==="
  purpose_policy: "preserve_or_todo"
```

### 4.9. CLI
```
ast_toc start
ast_toc stop
ast_toc status
```

## 5. Нефункциональные требования
- Python ≥ 3.10, Windows/Linux/macOS.
- Зависимости: `watchdog`, `pyyaml`.
- Latency реакции: ≤ 1 сек для 5k файлов.
- Генерация TOC для файла ≤ 500 строк: ≤ 100 мс.

## 6. Сценарии (Given–When–Then)
- Добавление TOC в новый файл.
- Обновление TOC при изменении.
- Игнорирование больших файлов.
- Управление демоном (start/stop/status).

## 7. Тестирование и приёмка
- Юнит-тесты: парсинг AST, генерация TOC.
- Интеграционные: мониторинг каталога.
- E2E: сценарии выше.
- Приёмка: TOC актуален ≤ 1 сек, повторный запуск не даёт диффов, покрытие ≥ 70%.
